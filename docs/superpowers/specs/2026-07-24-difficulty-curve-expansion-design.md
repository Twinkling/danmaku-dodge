# 难度曲线扩展设计

## 背景

当前版本已经具备开局保护、普通敌人、预判型敌人和分段难度，但实际试玩仍有三个明显问题：

- 开局速度倍率仅为 `0.45`，敌人接近玩家的过程偏慢。
- 难度仅在 `0、20、55、90` 秒附近形成变化，阶段层次不足。
- 90 秒后刷怪间隔、速度和敌人上限全部停止增长；高速敌人离场较快，实际场上数量通常达不到 18 个上限。

本轮只扩展现有难度曲线，不引入波次、技能、道具或新的敌人行为。

## 目标

- 开局第一批敌人更快进入有效躲避范围。
- 将持续加压过程扩展至 150 秒，并提供更清晰的中后段变化。
- 同时提高刷怪频率和敌人上限，让后期场上密度明显高于当前版本。
- 将最终速度倍率提高至 `2.00`，但通过阶段内插值平滑达到上限。
- 保持现有普通与预判敌人的玩法闭环和视觉识别。
- 继续使用少量参数控制难度，避免过度设计和过早优化。

## 非目标

- 不新增波次、高压期、动态难度或基于玩家表现的自适应逻辑。
- 不新增敌人类型、追踪、分裂、反弹或发射行为。
- 不增加生命、技能、道具、阶段提示或额外 HUD。
- 不改变倒计时动画、保护罩时长、玩家操作和计分规则。
- 不改变短边 `5%` 的最小出生距离。
- 不新增模块、资源、依赖或构建步骤。

## 难度曲线

难度继续由正式游戏的存活时间唯一决定。刷怪间隔和速度倍率在阶段内线性插值；敌人上限和预判型敌人比例在阶段边界切换。

| 正式时间 | 刷怪间隔 | 速度倍率 | 敌人上限 | 预判型敌人 |
|---|---:|---:|---:|---:|
| 0–15 秒 | 1.00 → 0.75 秒 | 0.70 → 0.90 | 12 | 0% |
| 15–35 秒 | 0.75 → 0.55 秒 | 0.90 → 1.10 | 20 | 25% |
| 35–60 秒 | 0.55 → 0.40 秒 | 1.10 → 1.35 | 30 | 25% |
| 60–90 秒 | 0.40 → 0.28 秒 | 1.35 → 1.60 | 42 | 50% |
| 90–120 秒 | 0.28 → 0.20 秒 | 1.60 → 1.80 | 56 | 75% |
| 120–150 秒 | 0.20 → 0.16 秒 | 1.80 → 2.00 | 72 | 75% |
| 150 秒后 | 0.16 秒 | 2.00 | 72 | 75% |

前 3 秒保护罩只是碰撞免疫状态，不是独立难度阶段。保护期内继续使用 0–15 秒曲线正常刷怪和移动敌人。

敌人上限只负责防止异常积压，不主动补齐数量。后期密度主要由刷怪间隔缩短产生；达到上限时仍暂停生成并清空刷怪积累。

## 状态与生成流程

`src/game-core.js` 继续通过纯函数 `getDifficulty(elapsed)` 返回：

- `protected`
- `spawnInterval`
- `speedMultiplier`
- `enemyCap`
- `predictiveRatio`

现有生成流程保持不变：

1. `stepGame()` 使用固定时间步推进正式游戏时间。
2. `updateEnemies()` 读取当前难度并累计刷怪时间。
3. 未达到敌人上限且刷怪间隔到期时生成一个敌人。
4. 敌人在出生时应用当前速度倍率和预判比例。
5. 已经在场的敌人保持出生时的速度，不随阶段变化突然加速。
6. 达到敌人上限时清空刷怪积累，避免敌人离场后集中补刷。
7. 150 秒后所有难度参数保持最终值，不再继续增长。

普通敌人和预判型敌人继续共享生成、移动、碰撞、越界清理和窗口缩放逻辑。现有随机速度范围、尺寸范围、颜色和预判提前量均不改变。

## 边界与公平性

- 非有限或负数时间继续按 0 秒处理。
- `15、35、60、90、120、150` 秒边界必须返回有限且连续的刷怪间隔与速度倍率。
- 敌人上限在阶段边界直接提高，不删除或补生成已有敌人。
- 保护期内敌人碰撞继续被忽略，保护结束后立即恢复正常判定。
- 短边 `5%` 的最小出生距离保持不变，生成点最多尝试 8 次。
- `2.00` 倍速度与短出生距离组合需要人工检查边缘场景；如果出现明显无法反应的碰撞，只回调后期速度曲线，不增加临时保护或新机制。
- 72 个敌人是安全上限，不是每局必须达到的目标数量。

## 自动化验证

更新核心测试以覆盖：

- `0、15、35、60、90、120、150` 秒及各阶段边界前一刻的完整难度参数。
- 刷怪间隔和速度倍率在相邻阶段之间连续。
- 敌人上限依次为 `12、20、30、42、56、72`。
- 预判型敌人比例依次为 `0%、25%、25%、50%、75%、75%`。
- 速度倍率在 150 秒达到 `2.00`，之后不再增长。
- 前 3 秒保持碰撞免疫，同时沿用第一阶段的刷怪参数。
- 敌人只在生成时应用当前速度，已有敌人不会被追溯加速。
- 达到敌人上限后暂停生成并清空刷怪积累。
- 重开后时间、保护状态、敌人和刷怪积累正确归零。
- 现有倒计时、输入、碰撞、结算、持久化和浏览器入口测试继续通过。

完整验证命令：

```bash
npm run check
git diff --check
```

## 人工试玩验收

通过本地 HTTP 服务分别使用鼠标和键盘试玩，重点确认：

- 开局约 1 秒出现首个敌人，速度明显快于当前版本。
- 前 15 秒已经形成躲避压力，但保护结束时不会稳定产生无法反应的贴脸碰撞。
- 35、60、90、120 秒后的速度与密度变化能够被感知。
- 60 秒后屏幕不再频繁出现大面积空白。
- 120 秒后形成持续高压，改变移动方向仍能躲避预判型敌人。
- 150 秒最终难度下画面、输入、碰撞和结算保持流畅。
- 玩家靠近四条边缘时，短边 `5%` 出生距离与最高速度的组合仍然公平。

只有在自动化验证全部通过且人工试玩确认完整闭环后，本轮玩法调整才视为完成。
