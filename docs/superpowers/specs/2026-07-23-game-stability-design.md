# 弹幕躲避稳定性与工程化设计

## 背景

当前项目是一个可直接静态部署的单页 Canvas 小游戏，已具备开始、移动躲避、敌人生成、碰撞、计分、最高分保存、结束和重开等核心闭环。现有实现把状态、规则、输入和渲染全部放在 `index.html` 中，并按动画帧计算时间、移动和刷怪，因此不同刷新率设备上的实际游戏速度和得分不一致，也缺少可独立验证的核心逻辑。

## 目标

本次优化将项目提升为可稳定部署、跨刷新率行为一致、具备最小工程保障的单页游戏版本，具体目标如下：

- 在 60Hz、120Hz 和 144Hz 等刷新率下保持一致的计时、移速和刷怪节奏。
- 修复游戏结束后的粒子、震动和新纪录判断。
- 支持鼠标、触摸、方向键和 WASD 操作，以及 Enter/空格开始或重开。
- 在窗口缩放和屏幕旋转时保持游戏对象的相对位置。
- 将纯游戏规则与浏览器输入、渲染和存储解耦。
- 使用 Node 内置测试覆盖关键规则，不引入运行时或测试依赖。
- 保持项目可以通过普通静态文件服务器直接部署。

## 非目标

- 不引入 Vite、React 或其他前端框架。
- 不增加关卡、道具、音效、账号、联网排行榜等新玩法。
- 不重做现有视觉风格。
- 不要求直接通过 `file://` 协议运行；ES Module 版本通过静态服务器访问。

## 文件结构

```text
.
├── index.html
├── package.json
├── README.md
├── src
│   ├── game-core.js
│   └── game.js
└── tests
    └── game-core.test.js
```

### `src/game-core.js`

纯 JavaScript 游戏规则模块，不访问 DOM、Canvas、`localStorage` 或 `requestAnimationFrame`。它负责：

- 创建初始状态和开始新一局。
- 将每个动画帧的真实经过时间转换为有上限的固定步长更新。
- 按固定时间步长更新玩家、敌人、粒子、震动、计时和难度。
- 生成敌人并执行边界清理与碰撞判断。
- 结束游戏并产生日志无关的结果状态，如最终得分和是否刷新纪录。
- 在画布尺寸变化时按比例迁移对象坐标并重算尺寸。

随机数通过函数参数注入，生产环境使用 `Math.random`，测试使用确定性随机数，从而稳定验证敌人生成和碰撞行为。

### `src/game.js`

浏览器适配层，负责：

- 初始化 Canvas、高 DPR 缩放和页面尺寸监听。
- 收集鼠标、触摸和键盘输入，并转换为核心模块可消费的输入状态。
- 管理 `requestAnimationFrame` 时间戳，并把真实经过时间传给核心模块。
- 绘制背景、游戏对象、分数、开始页和结束页。
- 安全读取和写入最高分。
- 更新辅助技术可读取的状态文本。

### `index.html`

只保留页面结构、基础样式、Canvas、无障碍说明和模块入口。Canvas 可聚焦，并通过 `aria-label` 与说明文本明确鼠标、触摸和键盘操作方式。状态区域使用 `aria-live="polite"` 播报开始、结束和新纪录，不逐帧播报分数。

## 状态与数据流

游戏状态使用 `idle`、`running`、`gameover` 三种明确阶段：

1. 页面加载后创建 `idle` 状态并读取最高分。
2. 点击、触摸、Enter 或空格触发新一局，状态转为 `running`。
3. 每个动画帧把真实经过时间传给核心模块；核心模块通过状态内的累加器以固定的 `1 / 60` 秒步长推进。
4. 核心模块返回更新后的状态，渲染层只读取状态并绘制。
5. 碰撞发生后状态转为 `gameover`，冻结玩家和敌人逻辑，但粒子与震动继续更新至自然结束。
6. 浏览器适配层仅在严格刷新纪录时写入最高分。

核心状态至少包含画布尺寸、阶段、固定步长累加器、玩家、敌人、粒子、存活时间、刷怪计时、刷怪间隔、震动量、最终得分和本局新纪录标记。

## 时间与难度模型

- 所有速度使用“逻辑像素/秒”，所有计时使用“秒”。
- 动画循环将单次真实经过时间限制在 `0.1` 秒以内，避免页面恢复时一次补算过长时间。
- 固定步长为 `1 / 60` 秒，每帧最多执行有限次数的补算；超过上限的积压时间丢弃，以响应性优先。
- 玩家跟随指针使用基于指数衰减的时间无关插值，保持现有柔和跟随感。
- 刷怪间隔从现有约 `28 / 60` 秒开始，逐次降低至约 `5 / 60` 秒；敌人速度由现有每帧速度换算为每秒速度，尽量保持 60Hz 下的原有手感。
- 分数直接来源于模拟存活时间，界面显示向下取整后的秒数。

## 输入设计

- 鼠标和单指触摸设置目标位置，玩家以时间无关插值追随目标。
- 方向键和 WASD 以固定的每秒速度移动玩家；按键状态支持同时按下两个方向。
- 最近一次有效输入决定当前控制方式，避免指针目标与键盘移动互相拉扯。
- Enter 和空格仅在 `idle` 或 `gameover` 阶段开始新一局。
- 页面失焦时清空按键状态，避免按键释放事件丢失后持续移动。
- 玩家位置始终限制在画布边界内。

## 尺寸变化

Canvas 的物理尺寸根据 DPR 设置，逻辑坐标保持 CSS 像素。窗口变化时：

- 玩家、敌人和粒子的坐标按新旧宽高比例迁移。
- 玩家和敌人尺寸按新旧短边比例调整。
- 速度按短边比例调整，保持相对屏幕速度。
- 指针目标同步迁移并重新限制在边界内。
- DPR 最大值继续限制为 3，以控制移动设备上的显存和绘制成本。

## 纪录与错误处理

- 开局时记录本局开始前的最高分。
- 结束时仅当最终整数秒数严格大于旧最高分才设置 `isNewRecord`。
- `localStorage` 的读取、解析和写入均包裹在异常处理内；无痕模式或存储被禁用时游戏仍可运行，只是不持久化纪录。
- 读取到非有限数值、负数或无效文本时回退为 0。
- Canvas 2D 上下文不可用时，在页面状态区域显示明确错误信息，并停止初始化动画循环。

## 测试策略

`tests/game-core.test.js` 使用 `node:test` 和 `node:assert/strict`，至少覆盖：

- 新建状态和开始新一局时的字段重置。
- 等量模拟时间在不同时间切片下得到一致分数和近似一致位置。
- 刷怪间隔随难度降低但不突破下限。
- 玩家边界限制和敌人越界清理。
- 碰撞切换到 `gameover` 并产生粒子、震动和最终得分。
- 游戏结束后粒子继续衰减、震动继续归零，敌人保持冻结。
- 追平旧纪录不标记新纪录，严格超过时才标记。
- 尺寸变化按比例迁移坐标、尺寸和速度。

`npm test` 运行核心测试，`npm run check` 依次执行源码语法检查和全部测试。由于项目没有构建步骤，验证还包括：

- 通过本地静态服务器访问页面并确认 HTTP 200。
- 桌面尺寸与高 DPR 下完成开始、移动、碰撞和重开闭环。
- 移动端竖屏尺寸下检查布局和触摸入口。
- 使用键盘完成开始、移动和重开。
- 检查浏览器控制台没有错误或警告。

## 验收标准

- `npm run check` 退出码为 0，所有自动化测试通过。
- 源码不再使用帧数作为秒数、移动距离或刷怪时间的直接依据。
- 60Hz、120Hz 和 144Hz 对应的模拟切片测试结果一致。
- 游戏结束特效可自然结束，追平最高分不会显示“新纪录”。
- 鼠标、触摸入口和键盘控制均可启动游戏，键盘可以连续移动角色。
- 桌面与移动端尺寸渲染正常，高 DPR Canvas 物理尺寸正确。
- README 包含运行、测试、操作和静态部署说明。
- 工作区只包含本次目标相关改动，不提交生成物或依赖目录。
