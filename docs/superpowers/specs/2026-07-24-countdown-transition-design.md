# 独立倒计时与保护罩衔接设计

## 背景

当前版本将“准备 3、2、1”、开局保护、玩家移动和正式计分放在同一个 3 秒阶段。实际试玩后，倒计时语义不够清楚：游戏在数字消失前已经开始计时，保护罩也在倒计时期间显示。

本次修订将倒计时从正式游戏中拆出，并用与玩家死亡粒子一致的方块粒子完成视觉衔接。

本设计覆盖 `2026-07-23-gameplay-pacing-design.md` 中关于开局 3 秒计分、保护期移动和“准备”文案的规则；难度曲线、公平刷怪、敌人上限和 60–90 秒目标保持不变。

## 目标

- 点击或按键后先完成独立倒计时，再开始正式计分和移动。
- 倒计时只显示 `3`、`2`、`1`，不显示“准备”文案。
- 数字使用方块粒子聚合，保持与玩家方块和死亡爆裂相同的视觉语言。
- `3`、`2` 聚合后向外炸散；`1` 聚合后直接回流到玩家。
- `1` 的粒子接近玩家时，保护罩逐渐成形；完全成形后正式开始。
- 保持实现边界清楚，不增加音效、技能、复杂场景或新的玩法系统。

## 非目标

- 不调整既有难度曲线、刷怪间隔、速度倍率或敌人上限。
- 不增加生命、护盾次数、无敌道具或其他玩家能力。
- 不增加“GO”、阶段名称、进度条或额外提示文字。
- 不增加音频资源、图片资源、构建依赖或动画框架。
- 不修改发布方式，不 push，不恢复 GitHub Pages 或 CI/CD 工作。

## 状态模型

游戏状态按以下顺序流转：

```text
idle → countdown → running → gameover
          ↑                      |
          └────── restart ───────┘
```

新增 `countdown` 阶段和独立的 `countdownElapsed`：

- `idle`：等待用户开始。
- `countdown`：推进倒计时时钟；玩家冻结、正式时间保持 0。
- `running`：正式计分、移动、开局保护和难度曲线开始生效。
- `gameover`：保留现有结算、最高分和粒子效果。

开始或重开调用倒计时入口，而不是直接进入 `running`。倒计时完成后，核心状态转换为 `running`，并保证：

- `elapsed = 0`
- `spawnElapsed = 0`
- 玩家仍位于画布中心
- 敌人和旧粒子为空

倒计时期间输入事件可以继续被监听，但核心不移动玩家。用户在倒计时结束时仍保持的键盘方向或鼠标目标，从第一个正式游戏步开始生效，不提前改变玩家位置。

## 时序

倒计时数字不代表真实秒数。每个数字占用 1.6 秒，最后增加 0.8 秒的回流衔接，总时长为 5.6 秒。

| 全局时间 | 内容 | 进场 | 清晰停留 | 退场 |
|---|---|---:|---:|---:|
| 0–1.6 秒 | `3` | 0–0.42 秒聚合 | 0.42–1.12 秒 | 1.12–1.6 秒向外炸散 |
| 1.6–3.2 秒 | `2` | 0–0.42 秒聚合 | 0.42–1.12 秒 | 1.12–1.6 秒向外炸散 |
| 3.2–4.8 秒 | `1` | 0–0.42 秒聚合 | 0.42–1.6 秒 | 不向外炸散 |
| 4.8–5.6 秒 | `1` 的粒子 | — | — | 直接回流到玩家 |

保护罩在回流衔接的后半段，也就是 5.2–5.6 秒之间从玩家中心逐渐扩张。此时它只是倒计时转场的一部分，游戏仍未计分、不可移动，也不生成敌人。

5.6 秒到达后：

- 保护罩完全成形。
- 阶段切换为 `running`。
- 正式分数从 0 秒开始。
- 玩家可以移动。
- 既有 3 秒开局保护开始计时，期间不生成敌人。

3 秒正式保护结束后，难度曲线从热身基线继续推进。倒计时的 5.6 秒不计入存活时间、最终分数或难度时间。

## 核心数据流

`game-core.js` 负责确定性时序，不负责粒子图形：

- 提供倒计时总时长和分段常量。
- 提供开始倒计时的状态入口。
- 在 `countdown` 阶段只推进 `countdownElapsed`。
- 到达总时长后切换到正式游戏。
- 在 `countdown` 阶段冻结 `elapsed`、玩家、敌人、刷怪积累和碰撞。

`game.js` 根据 `phase` 和 `countdownElapsed` 派生画面：

- 当前数字。
- 当前数字的局部进度。
- 聚合、停留、外炸或回流阶段。
- 保护罩成形进度。

动画进度不写入核心状态，也不创建新的玩法实体。

## 粒子渲染

数字粒子在浏览器入口中一次生成并缓存：

1. 在小型离屏 Canvas 上绘制当前数字。
2. 按固定网格读取不透明像素。
3. 将采样点转换为有上限的方块粒子模板。
4. 使用粒子索引生成确定性的方向、距离和轻微曲线。
5. 窗口尺寸或字体尺寸变化时按需重建缓存。

渲染约束：

- 每个数字的粒子数量设置明确上限，避免高分辨率画布导致数量失控。
- 同一数字和尺寸复用缓存，不在每帧读取像素。
- 聚合和炸散只计算显示位置，不向游戏状态写入粒子数组。
- 倒计时粒子使用白色；`1` 回流时逐渐过渡到青色。
- `3`、`2` 阶段不绘制外层保护罩。
- `1` 回流后半段才绘制保护罩扩张。

## 画面与交互

- 倒计时期间 HUD 分数始终显示 `0 秒`。
- 玩家保持居中，只绘制本体；`3`、`2` 阶段不绘制保护罩。
- `1` 回流完成后，正式游戏沿用现有轻微脉冲保护罩。
- `idle` 和 `gameover` 的现有提示保持不变。
- 点击、Enter 或空格从 `idle` / `gameover` 进入完整倒计时。
- 重开不会跳过倒计时。
- 无障碍状态在倒计时开始时提示“倒计时开始”，正式切换时提示“游戏开始”；不逐个朗读数字。

## 降级与异常处理

- 主 Canvas 2D 不可用时，保留现有可见错误处理。
- 离屏 Canvas 创建失败、2D context 不可用或像素读取抛错时，回退为普通实心数字的缩放与淡入淡出。
- 降级只影响粒子表现，不影响 5.6 秒时序、状态转换或正式游戏开始。
- 非有限或负数倒计时时间按 0 处理；超过总时长的显示进度夹取到完成状态。

## 自动化验证

核心测试覆盖：

- 开始和重开进入 `countdown`。
- 倒计时期间正式时间、玩家位置、敌人和刷怪积累保持冻结。
- 5.6 秒前不进入 `running`，到达边界后正式时间从 0 开始。
- 正式开始后仍执行现有 3 秒保护和难度曲线。
- `gameover`、最高分、碰撞和现有重开行为不回归。

浏览器入口测试覆盖：

- 页面不再绘制“准备”文案。
- 3、2、1 的显示区间和 1.6 秒节奏正确。
- `3`、`2` 使用外炸路径，`1` 使用回流路径。
- `3`、`2` 阶段没有保护罩。
- 5.2 秒前保护罩未出现；5.2–5.6 秒逐渐成形。
- 正式开始后数字消失、保护罩完整显示。
- 离屏 Canvas 失败时使用实心数字降级，且游戏仍可开始。
- 点击、Enter、空格和现有 Canvas 错误路径继续通过。

完整验证继续执行：

```bash
npm run check
git diff --check
```

## 人工验收

在本地 HTTP 服务中验证：

- 点击和键盘都能进入完整倒计时。
- 倒计时期间玩家不移动、分数为 0、没有敌人。
- `3`、`2` 外炸，`1` 回流，保护罩按设计成形。
- 保护罩完全成形后才开始计时和移动。
- 正式保护结束后敌人按现有曲线生成。
- 碰撞、结算、点击和空格重开完整可用。
- 页面控制台无 error 或 warning。

完成技术验证后，重新进行鼠标 3 局、键盘 3 局试玩。60–90 秒目标按正式计分时间判断，不包含倒计时。
