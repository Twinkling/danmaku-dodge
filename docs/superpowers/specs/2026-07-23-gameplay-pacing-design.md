# 游戏节奏优化设计

> 2026-07-24 修订：独立倒计时、计分起点和保护罩衔接以
> `2026-07-24-countdown-transition-design.md` 为准；本文中的难度曲线、
> 公平刷怪和人工验收目标继续有效。

## 背景

当前版本已经具备稳定的状态推进、输入、碰撞、结算和重开能力，但开局刷怪与速度增长过快，真实试玩可能在数秒内结束。下一阶段暂停发布与工程化工作，优先让核心躲避循环公平、可理解，并达到适合轻量游戏的单局时长。

## 目标

- 普通新玩家的单局中位存活时间达到 60–90 秒。
- 保持一击结束和连续加压的玩法特点。
- 提供 3 秒开局保护，让玩家先完成定位和控制适应。
- 通过少量、明确的参数形成可持续调优的难度曲线。

## 非目标

- 不增加生命、护盾、技能、道具或新敌人类型。
- 不增加波次系统、设置页面或复杂状态机。
- 不修改发布方式，不 push，不实施 GitHub Pages 或 CI/CD。
- 不把玩法逻辑重新合并到 `index.html`。

## 难度曲线

难度只由独立倒计时完成后的正式存活时间决定。刷怪间隔和速度倍率在相邻阶段之间线性插值，避免突然跳变；场上敌人上限按阶段采用固定整数。

| 时间 | 节奏 | 刷怪间隔 | 速度倍率 | 场上敌人上限 |
|---|---|---:|---:|---:|
| 0–3 秒 | 开局保护 | 1.25 秒 | 0.28 | 4 |
| 3–20 秒 | 热身 | 1.4 → 0.9 秒 | 0.45 → 0.7 | 6 |
| 20–55 秒 | 稳步加压 | 0.9 → 0.55 秒 | 0.7 → 1.0 | 12 |
| 55–90 秒 | 高压阶段 | 0.55 → 0.32 秒 | 1.0 → 1.3 | 18 |
| 90 秒后 | 保持高难度 | 0.32 秒 | 1.3 | 18 |

分数按正式游戏存活秒数计算，包含 3 秒开局保护，但不包含独立倒计时。

## 状态与数据流

`game-core.js` 提供纯函数 `getDifficulty(elapsed)`，返回当前刷怪间隔、速度倍率和敌人上限。`stepGame` 使用该结果推进刷怪：

- 正式游戏的保护期内玩家可以移动，并会生成低速预热敌人；保护期只免除碰撞死亡，不冻结刷怪。
- 敌人生成时确定速度；已经存在的敌人不会随阶段变化突然加速。
- 达到场上敌人上限时跳过本次生成，并清空本轮刷怪积累，避免稍后集中补刷。
- 敌人仍从屏幕外生成；候选生成点与玩家的距离小于短边 20% 时重新选择。
- 生成点最多尝试 8 次；全部失败时安全跳过，不进入无限循环。
- 重开会重置计时、刷怪积累和难度。

输入、最高分、碰撞和持久化逻辑保持不变。

## 画面反馈

- 独立倒计时只显示 `3`、`2`、`1`，具体粒子时序以 2026-07-24 修订设计为准。
- `1` 的粒子回流后保护罩成形，正式保护期内保持轻微脉冲。
- 正式保护结束后保护罩自动消失。
- 不为阶段、敌人上限或难度数值增加额外界面。

## 自动化验证

- `getDifficulty()` 在 3 秒时从保护期进入热身基线；20、55、90 秒边界保持连续；敌人上限始终使用对应阶段的固定整数。
- 正式保护期允许玩家移动、自然生成低速预热敌人，并且碰撞不会结束游戏。
- 生成点不会贴近玩家；固定尝试失败时跳过生成。
- 达到敌人上限后停止生成，不积累刷怪债务。
- 敌人的速度倍率在生成时应用，已有敌人不被追溯修改。
- 重开后保护期、难度和计时归零。
- 现有回归测试继续全部通过。

## 人工试玩与验收

通过本地 HTTP 服务完成鼠标 3 局、键盘 3 局试玩，记录存活时间和死亡原因：

- 中位存活时间目标为 60–90 秒。
- 明显低于 60 秒时，只调整曲线参数。
- 明显高于 90 秒时，只调整后半程参数。
- 不通过临时增加生命、护盾或技能来掩盖节奏问题。
- 最终确认开始、移动、碰撞、结算和重开完整可用。

本轮通过后再设计敌人内容或角色能力；发布工作继续保持暂停。
